# Scope, Assumptions, Constraints, and Open Questions

> **Simulation notice:** This register is a fictional discovery artifact. Assumptions are hypotheses to validate, not verified organisation facts.

## Scope boundaries

| In scope | Out of scope |
|---|---|
| End-user technology assets: laptops, desktops, phones, monitors, tablets | Servers, software licences, facilities inventory, and network infrastructure |
| Receipt/registration, assignment, return, repair, sanitisation and disposal | Production platform build, migration, integration, or procurement |
| Register fields, owners, lifecycle state, data quality, event evidence | Endpoint security and detailed sanitisation implementation |
| Return/warranty visibility and operational dashboard prototype | Accounting/depreciation policy and financial reporting certification |
| Business analysis, synthetic-data analysis, proposed UAT and governance | Real personal data or actual business outcome claims |

## Assumptions register

| ID | Assumption | Validation / owner |
|---|---|---|
| A-01 | The first increment can use a standardised minimum register before selecting a new platform. | Validate with sponsor and Enterprise Architecture |
| A-02 | A unique asset identifier can be established or reconciled across source systems. | Profile sources with Procurement, IT, and Finance |
| A-03 | Custodian references can use a minimised internal ID instead of names in routine reporting. | Confirm with Privacy and HR |
| A-04 | A designated asset steward can own record quality and status definitions. | Confirm operating model with IT leadership |
| A-05 | Required sanitisation has an approved policy and evidence artefact. | Confirm with InfoSec and Records |
| A-06 | The 19 October 2026 cut-off is suitable for deterministic sample dashboard examples only. | This is a simulation constant, not a production assumption |

## Constraints and dependencies

- Source-system access, API availability, procurement, and funding are unknown.
- A real rollout depends on privacy/security review, change support, training, and data cleansing.
- Calendar/timezone/holiday rules for due dates must be agreed.
- Sample values are synthetic and cannot be used for a production migration.
- Proposed performance/accessibility targets require an agreed test environment and verification method.

## Open questions

1. Which source is authoritative for receipt, assignment, custodian, warranty, and disposal?
2. How are devices identified where a serial is missing, duplicated, or replaced?
3. What constitutes an active asset for operational, finance, and warranty views?
4. Which events trigger return workflow, and who owns overdue escalation?
5. What evidence and approval are mandatory for each disposal path?
6. What data retention, legal hold, access, and audit policies apply?
7. What are expected report freshness, accessibility, service hours, and recovery needs?
8. Which user groups and sample cases should validate a pilot?
